B-дерево (B-tree) — сбалансированная древовидная структура, эффективная для поиска, диапазонных запросов и сортировки.
@@s05631
Представление (VIEW)
@@s05632
Сохранённый SQL-запрос, который выглядит как виртуальная таблица; не хранит данные отдельно от исходных таблиц.
@@s05633
Триггер (trigger)
@@s05634
Программный блок, автоматически срабатывающий при событии (INSERT/UPDATE/DELETE) над конкретной таблицей.
@@s05635
Хранимая процедура (stored procedure)
@@s05636
Программный блок на стороне СУБД, который вызывается явно по имени — в отличие от триггера, который срабатывает автоматически.
@@s05637

@@s05638

@@s05643
CAP-теорема — что означают буквы?
@@s05644
Consistency (согласованность), Availability (доступность), Partition tolerance (устойчивость к разделению сети). Распределённая система может гарантировать одновременно не более двух из трёх при разделении сети.
@@s05645
Резервное копирование: full backup vs incremental backup
@@s05646
Полное копирование сохраняет все данные целиком; инкрементное — только изменения с момента последней резервной копии (для восстановления нужны последний full-бэкап и все incremental после него).
@@s05647
Сортировки сравнением
@@s05648
Сравнивают пары элементов. Нижний теоретический предел худшего случая — O(n log n).
@@s05649
Пузырьком
@@s05650
Лучший случай O(n) достигается ТОЛЬКО с флагом раннего выхода: на уже отсортированном массиве один проход без обменов — и стоп. Без флага всегда O(n²).
@@s05651
Вставками
@@s05652
На почти отсортированных данных каждый элемент сдвигается недалеко — отсюда лучший случай O(n). Быстра на малых и почти упорядоченных массивах, используется внутри Timsort.
@@s05653
Выбором
@@s05654
O(n²) ВСЕГДА, даже на отсортированном массиве: чтобы выбрать минимум, всё равно нужно просмотреть весь остаток. Зато делает не более n−1 обменов — минимум среди простых сортировок.
@@s05655
Слиянием
@@s05656
Гарантированные O(n log n) в любом случае (делит пополам log n раз, на каждом уровне слияние за O(n)). Цена — O(n) дополнительной памяти под слияние. Хорошо подходит для связных списков и внешней сортировки.
@@s05657
Быстрая
@@s05658
На практике обычно быстрее merge sort (хорошая работа с кэшем, in-place). Худший случай O(n²) — при неудачном pivot (напр. всегда первый элемент на отсортированных данных); случайный pivot или «медиана трёх» его почти исключают.
@@s05659
Пирамидальная
@@s05660
Единственная из «быстрых» с гарантией O(n log n) И памятью O(1) одновременно. Строит кучу за O(n), затем n раз извлекает максимум за O(log n). Обычно медленнее quicksort из-за плохой локальности обращений к памяти.
@@s05661
Шелла
@@s05662
Улучшенная сортировка вставками: сравнивает элементы на расстоянии «шага», постепенно уменьшая его. Точная сложность ЗАВИСИТ от последовательности шагов; с наивными шагами худший случай деградирует до O(n²).
@@s05663
Сортировки без сравнений
@@s05664
Не сравнивают элементы попарно, а используют их значения как ключи/индексы. Поэтому обходят предел O(n log n). k — диапазон значений, d — число разрядов.
@@s05665
Подсчётом
@@s05666
Считает, сколько раз встречается каждое значение, и расставляет по местам. Эффективна, когда диапазон значений k невелик и известен заранее (напр. оценки 0–100). При огромном k память O(k) становится неподъёмной.
@@s05667
Поразрядная
@@s05668
Сортирует поразрядно (обычно counting sort по каждому разряду), от младшего к старшему. Здесь k — число разрядов/проходов. Хороша для чисел и строк фиксированной длины.
@@s05669
Карманная
@@s05670
Раскидывает элементы по «корзинам» по диапазонам, сортирует каждую и склеивает. Хороша при равномерном распределении данных; если все элементы попадут в одну корзину — деградирует до O(n²).
@@s05671
Гибрид сортировки вставками и слиянием; штатная сортировка в Python (sorted/list.sort) и Java (для объектов). Находит уже упорядоченные участки («runs»), поэтому на почти отсортированных данных доходит до O(n).
@@s05672
Линейная / логарифмическая — быстро
@@s05673
Линеарифмическая — оптимум для сравнений
@@s05674
Квадратичная — медленно на больших n
